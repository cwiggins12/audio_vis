Shader Authoring Guide

Everything you need to write shaders for audio_vis.

Getting Started

Each shader lives in its own subdirectory inside shaders/. At minimum, it needs a file named frag.glsl (your fragment shader). If you want to override any audio or feedback defaults, add a spec.cfg alongside it. The directory and frag.glsl must exist before the engine starts for it to be recognized (for now). The window title shows the subdirectory name when the shader is selected.

The engine automatically prepends a header to your frag.glsl that provides uniforms, SSBOs, helper functions, and a built-in bitmap font. You only need to write a void main() and set FragColor. A copy of the header can be found in the same directory as this document if you would like to look at it directly.

Shaders and specs hot-reload on save. Edit either file while the program is running and the engine will detect the change and reload automatically. If your shader has a compile error or your spec has a parse error, the engine will display an error message on screen pointing you to the erroneous file, give you more detail in the log.txt in the audio_vis root directory, and restore your working version on the next successful save of an error-free shader.

Minimal Example

void main() {
    vec2 uv = uvBottomLeft();
    int bin = int(uv.x * float(fftArrSize));
    float val = fftData[clamp(bin, 0, fftArrSize - 1)];
    FragColor = vec4(vec3(val), 1.0);
}

This draws the FFT output as a horizontal brightness gradient. No spec.cfg needed. Without it, the defaults will be used.

Audio Device Selection

On startup, audio_vis will default to the system default audio device. At any point, you can press BACKSPACE to enter the device selection menu. It shows a numbered list of available playback devices you can use as a source (up to 10). Press the associated number key of the device you want to use. If you do not wish to choose a device, pressing BACKSPACE again will exit the menu.

SSBOs and Their Formatting

peakRMSData[]: binding 0, readonly

Peak and RMS measurements. Layout depends on isPeakRMSMono:

Stereo (default): [L_peak, L_rms, R_peak, R_rms, ...]: 2 floats per channel

This interleaving pattern continues for any number of channels to accommodate any audio device

Mono (isPeakRMSMono = true): [peak, rms]: 2 floats total

Values are in dB (default) or linear magnitude depending on isPeakRMSdB.

fftData[]: binding 1, readonly

FFT output array. Length is fftArrSize. Value range depends on spec settings:

MeasurementRange
DECIBELS (default)-96.0 to 0.0 dB
MAGNITUDE0.0 to ~1.0
POWER0.0 to ~1.0 (squared magnitude)

prHolds[]: binding 2, readonly

Peak hold values for peak/RMS data. Same layout, formatting, and value measurements as peakRMSData[]. Only populated when getPeakRMSHolds = true.

fftHolds[]: binding 3, readonly

Peak hold values for FFT data. Same length, formatting, and value measurements as fftData[]. Only populated when getFFTHolds = true.

feedbackIn[]: binding 4, readonly

Previous frame's feedback buffer. Only available when feedbackBufferSize > 0. Use for ping-pong effects, spectrograms, trails, particle systems, etc.

feedbackOut[]: binding 5, writeonly

Write your feedback data here. Whatever you write appears in feedbackIn[] on the next frame. The engine handles all double-buffering internally.

rawSamples[]: binding 6, readonly

Raw samples of each new audio window. Layout depends on isRawSamplesMono:

Stereo (default): [L_0, R_0, L_1, R_1, ...]: hopSize floats per channel

This interleaving pattern continues for any number of channels to accommodate any audio device

Mono (isRawSamplesMono = true): [0, 1, 2, ...]: hopSize floats total

Values are in dB (default) or linear magnitude depending on isRawSamplesdB.

Text Rendering

A built-in CP437 bitmap font is available for on-screen text.

// Render a single character
float renderChar(int charCode, vec2 origin, float size, vec2 fragPx);

// Render a string from an int array
float renderText(int[128] chars, int len, vec2 origin, float size, vec2 fragPx, int offset);

Both return 1.0 where the glyph is drawn and 0.0 elsewhere. Use with mix() to color the text:

vec2 px = toPx();
int chars[128];
chars[0] = 72; // 'H'
chars[1] = 73; // 'I'
float text = renderText(chars, 2, vec2(10.0, 10.0), 32.0, px, 0);
FragColor = mix(backgroundColor, vec4(1.0), text);

Character codes are standard ASCII (32-126).

Textures

Load image files as textures by declaring them in spec.cfg and your shader.

In spec.cfg:

texture.<uniformName> = <filename>

Declare one per line. The uniform name becomes a sampler2D in your shader. The file must be in the same directory as frag.glsl. Path traversal (e.g. ../../other.png) is rejected for security. Do not place your textures in a subdirectory.

In frag.glsl:

uniform sampler2D <uniformName>

This pattern will ensure that your texture properly goes from a file in your shader's directory to the sampler2D in your shader

Supported formats: PNG, JPG, BMP, TGA, GIF(first frame only).

Fonts

Load image files as fonts by declaring them in spec.cfg and your shader.

In spec.cfg:

font.<uniformName> = <filename.ttf>

Declare one per line. The uniform name becomes two sampler2D variables in your shader. The file must be in the same directory as frag.glsl. Path traversal (e.g. ../../other.png) is rejected for security. Do not place your fonts in a subdirectory.

In frag.glsl:

uniform sampler2D <uniformName>
uniform sampler2D <uniformNameMetrics>

This pattern will ensure that your font properly goes from a file in your shader's directory to the sampler2D's in your shader

Supported format: TTF

Warning: Be sure to only use font files that you trust.

perceptualSlopeDegrees

Applies a frequency-dependent gain tilt to the FFT output. Common values:

ValueEffect
0.0Flat: white noise reference, analytical displays
3.0Pink noise reference: good general-purpose starting point
4.5Music-focused: extra high-end boost, popularized by FabFilter Pro-Q

FFT Temporal Smoothing

KeyTypeDefaultDescription
useFFTSmoothingbooltrueEnable temporal smoothing on FFT output
fftAtkfloat0.05Attack time in seconds (how fast values rise)
fftRlsfloat0.3Release time in seconds (how fast values fall)

Smoothing is asymmetric. You can have a fast attack to catch transients and a slow release for smooth decay. Values are converted to frame counts based on your display refresh rate. Setting either to 0.0 or below disables smoothing for that direction even if the bool is true.

FFT Holds

KeyTypeDefaultDescription
getFFTHoldsbooltrueEnable peak-hold tracking for FFT data
fftHoldTimefloat1.0Seconds to hold a peak before it starts dropping
fftHoldScalarfloat0.975Exponential decay multiplier after hold time expires

When enabled, fftHolds[] is populated with the same size as fftData[]. Each element tracks the highest value seen at that bin, holds it for fftHoldTime seconds, then decays exponentially by fftHoldScalar per frame until it either hits the minimum value or a new FFT value at its point is larger than the scaled value, which will cause the FFT value to be the new hold.

Feedback Buffer

This will allow for you to use data from a prior frame. Everything you write to feedbackOut[] will be the feedbackIn[] next frame

KeyTypeDefaultDescription
feedbackBufferSizeexpr0Size in floats. 0 = disabled. Supports expressions.
feedbackBufferScalesWithWindowenumNO_SCALEAuto-scale on resize
feedbackBufferInitValuefloat0.0Initial value for all elements on load/swap

The feedback system provides two SSBOs: feedbackIn[] (read previous frame) and feedbackOut[] (write this frame). The engine ping-pongs them automatically each frame.

Same expression variables and scaling modes as customFFTSize. Same double-scaling warning applies.

Size limit: Clamped to the smaller of 33,177,600 floats (the size of a 4K framebuffer) or your GPU's reported GL_MAX_SHADER_STORAGE_BLOCK_SIZE. At 4 bytes per float, 33M floats ≈ 126 MB.

Common patterns:

// Per-pixel RGBA feedback (full framebuffer)
feedbackBufferSize = WINDOW_HEIGHT * WINDOW_WIDTH * 4

// Scrolling spectrogram (256 mel bins, ~5 seconds)
feedbackBufferSize = 256 * 5 * SAMPLE_RATE * 4 / FFT_SIZE

// Fixed-size system
feedbackBufferSize = 4096

Expressions

customFFTSize and feedbackBufferSize accept math expressions using these variables:

VariableValue
WINDOW_WIDTHCurrent framebuffer width in pixels
WINDOW_HEIGHTCurrent framebuffer height in pixels
DISPLAY_HZMonitor refresh rate
NUM_CHANNELSAudio channel count
SAMPLE_RATEAudio sample rate
FFT_SIZERaw FFT window size
FFT_BIN_AMTRaw bin count (FFT_SIZE / 2 + 1)
Feedback Buffer Only Variables
FFT_ARR_SIZEThe size of the FFT array that is calculated from the customFFTSize expression, the audible bin amount, or the FFT_BIN_AMT depending on fftOutputMode
HOP_SIZEHop window size of the FFT on each new audio window
HOP_AMTAmount of hops to make it to an entirely new audio window

Supported operators: +, -, *, /, (). Result is truncated to an unsigned integer and errors can happen within the expression unless the expression at any point overflows type Double. Subtraction clamps to 0 if the right side is larger. Any errors in expressions will hard set the size to 0. Then, the error location is shown on the error shader onscreen, with more detail in log.txt.

Examples:

customFFTSize = 512
customFFTSize = WINDOW_WIDTH
customFFTSize = WINDOW_WIDTH * 1000 / 1280
feedbackBufferSize = (WINDOW_HEIGHT * WINDOW_WIDTH) * 4

For more examples, check out the spec.cfg in the example shaders that come with the engine

Tips

Shader not showing up in engine?

Make sure to have a shaders directory in the same location as your executable, a subdirectory in shaders with the name you want, and at minimum a frag.glsl within that subdirectory before the program runs. From there, any changes you make, will either show your shader or an error message showing you where the issue is

Watch out for a common driver bug in GL ES 3.1 on some drivers

On some drivers, shaders have incorrect logic when casts are done within some expressions. My way around it has been casting to a new variable and using that. There are plenty of examples of this in the fragment header and in many of the example shaders. Try doing this if you are getting incorrect results on lines that have casts in expressions.

Optimize hard when on the Pi

While this program does cost very little on the CPU, it can be very GPU heavy depending on the current shader. The Raspberry Pi 4, which is what this was tested on, has a substantially smaller GPU than even very low budget laptops. So, some shaders that are great on desktop may need more optimization to work well on the Pi

dB mapping helper

Most shaders working in dB mode will want a normalization function:


    float dbToT(float db) {
    return clamp((db - DB_MIN) / (DB_MAX - DB_MIN), 0.0, 1.0);
}

A range of -80.0 to 0.0 works well for most visualizations. Widen to -96.0 for quieter material, but there may be some artifacts from temporal smoothing around the noise floor.

Aspect ratio

Use ndcBottomLeftAR() or ndcTopLeftAR() whenever you're drawing circles, regular polygons, or SDFs. The non-AR versions will stretch on non-square windows.

Smoothing tradeoffs

Temporal smoothing at some value is generally recommended for most visualizations to reduce the artifacts that come from dramatic changes between audio windows. Fast attack + slow release (e.g. fftAtk = 0.05, fftRls = 0.3) gives reactive-but-smooth visuals, is set in the default setting, and is generally the recommended approach for more musical/artistic visualizers. Setting both to 0 or below gives raw unsmoothed data: useful for spectrograms and analytical displays. Matching attack and release gives symmetrical decay.

Perceptual slope

If your visualizer looks like the bass is always dominant and the highs are invisible, increase perceptualSlopeDegrees. 3.0 is a good starting point, 4.5 gives extra high-end boost. Set to 0.0 for flat/analytical displays.

newAudioWindow

Audio analysis doesn't run every display frame. It is dependent on sample rate and FFT hop size. Check newAudioWindow != 0 to only do heavy feedback writes when there's actually new data, and just read/pass-through on other frames.

Shader Author Checklist

  • shaders/ directory sits next to the audio_vis executable.
  • Create and name a new directory within the "shaders" directory
  • New directory contains frag.glsl with the minimal working code
  • frag.glsl compiles without errors (full glsl error log prints to log.txt)
  • spec.cfg parses without errors (spec errors/warnings will also print to log.txt)
  • Avoid hardcoded bin counts. Stick to using fftArrSize for FFT indexing
  • Feedback buffer reads use feedbackIn[], writes use feedbackOut[]
  • If necessary, feedback shaders pass through data on non-audio frames (newAudioWindow == 0)
  • Scales properly with window sizes and fullscreen mode
  • Texture and font files are directly in the shader directory (no path traversal)
  • Expression variables match scaling mode (be careful about double-scaling)
